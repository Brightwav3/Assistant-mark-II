## 2. Original failures and their actual causes

### `DELEGATION_RESULT_INVALID`

`conversation_recall -> ok` followed by `DELEGATION_RESULT_INVALID` meant the tool call itself completed, but the delegated model's final JSON failed broker validation. The broker expects `delegation.result.v1`, an object `data`, an array `references`, and valid evidence references. Conversation evidence originally could not satisfy the memory-only reference contract.

Fixed locally:

- delegation results may reference conversation turns using `turnId`;
- conversation recall can return evidence from episode turns, not only long-term `memoryId` references;
- broker validation accepts and verifies the bounded conversation-reference form.

### Misleading handoff trace

The original command used the human console logger. It prints `delegation.failed` but suppresses internal delegation lifecycle events and did not print `handoff.*` or `compaction.*`. Absence of `handoff.prepared` in that log was therefore not evidence that handoff did not run.

Fixed locally:

- every debug run writes a full raw JSONL trace under `.runtime\traces`;
- the terminal remains concise and shows only useful human-facing state;
- the raw trace preserves delegation, handoff and compaction events for later inspection.

### Episode and recall contamination

Three distinct problems existed:

- episode turns stored `meaning` where verbatim speech should remain available;
- recall searched persisted turns but did not retain both verbatim and normalized meaning cleanly;
- `[DELEGATION RESULT ...]` could enter `record_heard` as if it were user speech.

Fixed locally:

- verbatim and meaning are stored independently;
- uncertainty metadata is persisted with each episode turn;
- delegation-result payloads are rejected by `record_heard`;
- the SQLite episode schema is now version 4 with `conversation_turns.uncertain_parts`.

## 3. Implemented behavior

### Explicit memory creation

The delegated Tool System now exposes `memory_create`. It is allowed only when the current user utterance contains an explicit Czech memory instruction from these families:

- `zapamatuj si ...`
- `měj na paměti ...`
- `nezapomeň ...`

The runtime, not the model, owns session identity, source turn, subject and provenance. The tool validates that it is operating on the current user turn and deduplicates equivalent memories. MARK may then acknowledge naturally, for example „Píšu si“, „Budu na to myslet“ or „Pamatuji si“.

### Composite delegation

The realtime voice model previously sometimes called `intelligence_delegate` without first calling `record_heard`. `memory_create` then saw a stale latest turn and rejected the request.

`intelligence_delegate` is now composite. Its required input includes:

- `current_verbatim`
- `current_meaning`
- `current_language`
- `current_uncertain_parts`

The handler first captures the current turn, then builds recall context, then accepts the delegated request. When delegating, Gemini must not separately call `record_heard`; non-delegated utterances still use `record_heard` in debug mode.

### Confidence from speech uncertainty

`record_heard` carries structured uncertain spans:

```json
[
  {
    "text": "testovací",
    "uncertainty": "medium",
    "alternatives": []
  }
]
```

Mapping:

| Speech status | Stored confidence |
|---|---:|
| certain | 1.00 |
| low uncertainty | 0.75 |
| medium uncertainty | 0.50 |
| high uncertainty | 0.25 |

Confidence is computed only from uncertain spans actually used by the stored claim. Example: if „testovací“ is uncertain but the stored fact is only „káva bez cukru“, the fact may remain confidence 1.0. If the explicit memory trigger itself is uncertain, creation is rejected rather than silently persisting questionable intent.

### Recall prelude

Before each delegation, the Tool System performs a deterministic `conversation_recall` over the latest 20 episode turns and attaches the result as selected context. Therefore seeing `conversation_recall -> ok` during a memory-create request does **not** mean the model chose the wrong tool; it is an infrastructure prelude. The delegated model may then call `memory_search`, `memory_view`, `memory_create`, or the guarded `end_conversation` tool.

### Delegated conversation ending

When delegation is enabled, the voice model no longer owns a direct `end_conversation` tool. Ending goes through the delegated Tool System and requires:

1. a preceding user request to finish;
2. MARK's confirmation question;
3. a later user confirmation.

The delegated lifecycle result is forwarded back to the host shutdown request.

### ActionRuntime bounds

Per-request model/tool-call limits in Intelligence Core were corrected so one delegation cannot accidentally consume or inherit another request's counters.
